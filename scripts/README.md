# 공식 공연 데이터 1차 정제

Python 3.9 이상, 외부 패키지 및 네트워크 요청 없이 실행합니다.

```powershell
python scripts/clean_kspo_performances.py
python scripts/export_official_events.py
python -m unittest discover -s scripts -p 'test_clean_kspo_performances.py'
```

입력은 `data/kspo_performances.csv`이며 원본은 수정하지 않습니다.
출력은 Git에서 제외한 `data/processed/`에 저장됩니다.

- `kspo_performances.cleaned.json`: 공식 자료만 포함한 정제 결과
- `kspo_quality_report.json`: 원본 SHA-256, 컬럼별 채움 수, 중복·검토 사유 집계

다른 경로를 사용하려면 `--input 파일경로 --output-dir 출력폴더`를 지정합니다.
수집 시각을 알 수 없어 `collectedAt`은 null입니다. 파일 수정 시각이나
등록일을 수집 시각으로 대신하지 않습니다.

## 정제 규칙

- 모든 컬럼의 원래 값이 같은 행만 통합하고 CSV 원본 행 번호를 남깁니다.
  같은 제목만으로 합치지 않습니다. 서로 다른 회차가 사라질 수 있기 때문입니다.
- HTML 설명을 일반 텍스트로 바꾸고 공백을 정리합니다. 원본 HTML은 CSV에 남습니다.
  결과 텍스트를 HTML로 렌더링해서는 안 됩니다.
- 장소의 앞쪽 `올림픽공원 `을 제거하고 명시한 별칭만 정리합니다.
  예: 체조경기장 → KSPO DOME, K아트홀 → K-아트홀.
  이는 비교용 표기이며 당시 공연장의 이름은 `venueRaw`로 보존합니다.
- `regDate`는 `registeredAtRaw`에 보관하며 개최일로 사용하지 않습니다.
- `temporalCoverage` 전체가 유효한 연·월·일 하나일 때만 `startDate`를 채웁니다.
  시간만 있거나 연도가 없으면 날짜를 만들지 않습니다.
- 복잡한 일정의 완전한 날짜는 `dateCandidates`에 기록하지만 확정 일정이 아닙니다.
  축약 날짜, 회차, 예매일과 개최일 구분은 아직 처리하지 않습니다.
- 공식 출처는 `sourceType: official_public_data`, `isDemo: false`로 명시합니다.
  홈페이지 수집 자료와 가상 행사는 입력하거나 섞지 않습니다.
- 상세 링크, 종료일, 수집일을 임의로 만들지 않습니다.

## 해석과 다음 작업

전체 정제 결과는 1차 검토 자료입니다. `export_official_events.py`는 원본 공식 CSV만
읽어 제목이 있는 1,893건 중 관리용 항목 335건을 제외한 1,558건의 검색 자료를
`src/data/official-events.json`에 만듭니다.
이 파일은 웹에서 사용하는 배포용 스냅샷이므로 Git 공유 대상입니다.
설명문·등록일·인증키는 포함하지 않으며 원본 SHA-256과 CSV 행 번호를 보존합니다.
홈페이지 최신 공연이나 공지사항 CSV는 읽지 않습니다.

웹은 공식 자료의 행사명을 정확히 비교하고, 날짜가 없는 자료는 날짜 확인 불가로
처리합니다. 같은 이름의 자료가 여러 건이면 회차 확정 없이 확인 불가로 남깁니다.
홈의 공식 공공데이터 화면은 행사명·장소 검색과 페이지당 20건 조회를 지원합니다.
목록에서 '이 공식 자료와 비교하기'를 누르면 원본 식별자를 유지한 채 입력 화면으로
이동합니다. 같은 이름의 기록이 여러 개여도 사용자가 선택한 자료를 기준으로 비교합니다.
행사명을 바꾸면 기존 자료 선택을 해제합니다. 날짜·장소는 포스터 내용을 입력하도록
빈칸으로 두며, 원본에 없는 날짜를 자동으로 채우지 않습니다.
입력 화면의 공식 검색은 제목 일부를 입력하면 최대 10개의 후보를 보여줍니다.
최신 일정 목록은 `src/data/events.ts`의 가상 행사로 별도 구성하며 시연용 표시를 합니다.
가상 행사는 공식 공연 상세 링크를 갖지 않습니다.

시연 확인 순서:

1. '예시로 체험하기' → 가상 별빛 콘서트 → 일치, 시연용 안내 확인.
2. 같은 예시에서 날짜 또는 장소 변경 → 일부 다름, 시연용 안내 유지.
3. 날짜·장소를 비움 → 일부 항목 확인 불가.
4. 공식 자료의 행사명을 입력하고 후보 선택 → 공식 출처와 원본 행 표시,
   날짜 누락이면 확인 불가. 동명 자료가 여럿이면 회차 미확정 안내.
5. 존재하지 않는 행사명 입력 → 행사 확인 불가. 허위로 판정하지 않음.

가상 행사 일정은 2026년 11~12월 시연 기준이며 자동으로 최신화되지 않습니다.
다른 시점에 시연하려면 명시적으로 가상 일정을 갱신해야 합니다.

0건이라는 수치는 원본에 개최일이 전혀 없다는 뜻이 아니라,
현재의 보수적인 자동 확정 조건을 만족하는 행이 없다는 뜻입니다.

다음에는 `scheduleRaw`와 `descriptionText`를 검토하여 개최일이 명시된 패턴을
분류하고, 근거가 명확한 경우에만 날짜 추출 규칙을 추가해야 합니다.
설명문에는 예매일이나 다른 공연 날짜도 있을 수 있으므로 첫 날짜를
무조건 개최일로 채택해서는 안 됩니다.

웹의 ParkEvent는 날짜가 있는 시연 일정에만 사용하고, 공식 자료는 날짜 누락을
허용하는 별도 스냅샷으로 조회합니다. 공식 자료를 시연 일정 배열에 섞지 않습니다.
팀 코드의 OCR·인증·방문일 저장·달력 기능을 유지한 채 통합했습니다.
OCR 시연 후보와 행사 기반 주차 안내도 가상 자료임을 표시하며,
연도가 없는 OCR 날짜는 임의로 채우지 않습니다.
DB 스키마 및 Lovable 설정은 직접 수정하지 않습니다.

## 공식 포스터 연결과 담기

```powershell
python scripts/match_official_posters.py "다운로드한 공식 공연 포스터 정보 CSV 경로"
```

2025-05-08 기준 공식 포스터 CSV 201건을 대상으로 행사명·장소를 정규화한 뒤,
API와 포스터 양쪽의 후보가 각각 하나인 7건만 연결했습니다.
제목만 일치하는 다른 회차를 임의로 연결하지 않습니다.
원본 CSV는 수정하지 않으며 배포 자료는 `src/data/official-posters.json`,
검토 대상 194건은 로컬 `data/processed/poster-match-report.json`에 기록합니다.
포스터가 있는 행사를 목록 앞쪽에 보여줍니다.

연결한 7개 URL은 GET 범위 요청에서 image/jpeg와 JPEG 시그니처를 확인했습니다.
원본 서버는 HEAD 요청에는 404를 반환하므로 HEAD만으로 링크를 판정하지 않습니다.
원격 이미지가 나중에 사라지면 대체 아이콘을 표시합니다.
일정 원문은 포스터 자료 출처와 함께 별도로 표시하고 API 개최일로 자동 대체하지 않습니다.

공식 행사도 기존 Supabase event_saves와 집계 함수를 사용해 담기·취소·인원 집계를
지원합니다. 미확인 집계는 0명으로 꾸미지 않고 확인 중으로 표시합니다.
기존 DB에서 방문일이 필수이므로 개최일 미확인 자료는 사용자가 개인 방문예정일을
선택합니다. 이는 공식 일정이 아니며 방문 계획 달력에도 '개인계획'으로 표시합니다.
행사 ID로 서버 저장 자료를 복원하므로 다시 로그인해도 공식 행사 담기가 유지됩니다.
DB 스키마를 변경하거나 임의 날짜를 공식 개최일로 기록하지 않습니다.

## 행사명이 아닌 관리용 항목 제외

`export_official_events.py`에서 다음 항목을 목록·검색·비교용 스냅샷에서 제외합니다.

- 예약완료·준비대관·철거대관·대관예정·행사철거: 212건
- 주간행사 계획·주간계획·옥외 주간계획 등 종합 안내: 114건
- 수시대관 예약가능 일정: 1건
- 무대점검·내부공사·시설보수 등 시설 작업: 8건

제목 있는 자료 기준 제외 합계는 335건이고, 표시 자료는 1,558건입니다.
앞서 누락값으로 판정한 제목 4건을 포함하면 중복 정제 자료 1,897건 중 339건이
배포 대상에서 빠집니다. 원본 CSV와 1차 정제 결과는 보존합니다.
제외된 ID·제목·원본 행 번호·사유는 `data/processed/official-event-exclusions.json`에서
확인할 수 있습니다. 관리용 상태 제목은 완전 일치, 주간계획은 제목 시작 패턴으로
판정합니다. '기획'·'주간' 등의 단어가 있다는 이유만으로 공연을 삭제하지 않습니다.
나머지 자료 전부의 개최 여부·최신성까지 검증했다는 의미는 아닙니다.
